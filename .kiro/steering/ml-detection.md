# ML & Detection Standards (first-stage screening)

## Progression (BRD §13)

1. **Baseline A, rules only**: transparent reason codes (`AMT_GT_P99_CUSTOMER`, `NEW_DEVICE`,
   `VELOCITY_5M_GT_3`, `RECIPIENT_LINKED_FRAUD`, `LIMIT_UTIL_GT_90`, `NIGHT_TXN_UNUSUAL`).
2. **Features**: customer baseline (median, p95, MAD z-score, ratio to median), rolling counts and values
   (5m/1h/24h/7d), limit utilization, device novelty (`first_seen`, linked accounts), merchant
   familiarity, recipient fan-in/out, graph distance to known fraud.
3. **Baseline B, ML**: LightGBM classifier (`is_unbalance=True` or `scale_pos_weight`) + Isolation
   Forest anomaly score as a feature or as a parallel signal.
4. **Variant C (optional)**: ML + Jev routing, behind a flag.
5. **Variant D**: best screen + agentic Gemini investigation on candidates only.

## Rules that protect the benchmark

- **Time-based split** (e.g. days 1–60 train, 61–75 validation, 76–90 test). Never a random split.
- **Point-in-time features**: compute each transaction's features from strictly earlier data only. Add a
  unit test that fails if a feature uses future rows.
- Calibrate the candidate threshold on **validation**, report on **test**. Target candidate rate ~1–5%.
- Report: precision, recall, PR-AUC, false positives per 10k, candidate rate, fraud value captured,
  P50/P95 scoring latency. Write to `docs/metrics/detection_metrics.json` and `benchmark.json` with
  dataset seed, model version, and timestamp.
- **Never hand-type a metric** into code, UI, README, or deck. Read it from the JSON.

## Model versioning

`models/<name>-<yyyymmdd>-<shortsha>.txt|.joblib` + `models/registry.json`
`{active, versions:[{id, trained_at, features, metrics_ref}]}`. `get_ml_risk_score` returns
`{score, model_version, top_features}`.

## Performance

- Vectorize with pandas/numpy. Score the full dataset (thousands to hundreds of thousands of rows) in seconds.
- Single-transaction scoring (`POST /api/transactions/score`) should take < 100 ms P95 on Cloud Run (no LLM in this path).
- Keep model + features in memory at startup; load from GCS or the image.

## Synthetic data

Generated by `app/data/generate.py`, seeded and reproducible. See the `synthetic-fraud-data` skill for
the scenario mix. Labels exist only for evaluation. The scorer must never read the label column.

## Graph

NetworkX `MultiDiGraph` with node types (customer, account, device, merchant, recipient) and edges
(owns, used_device, paid, received_from). Precompute `known_fraud` node flags, shortest-path distance
to fraud, shared-device clusters, and recipient fan-in. `GET /api/network/{entity_id}` returns ≤ 2-hop
ego graph capped at ~150 nodes, ready for Cytoscape (`{nodes:[{data}], edges:[{data}]}`).
